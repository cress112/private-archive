2026-11-23の最新指示により実AWSのアプリ動作受入を開始した。AWS構成の参照・plan/apply・権限追加は禁止。以下の準備時点の記録に対し、実施中の結果・数量枠・復元待ちは [実AWS検証記録](AWS_VALIDATION.md) と [台帳](validation/aws-live.json) を優先する。
2026-11-22、D-10〜12で方針確定。最終フェーズP3-11のみで実施し、現時点ではAWS操作・リソース作成を行わない。追加費用合計1 USD以下で行い、同じIaC・リソースを試験後の運用へ引き継ぐ。

2026-11-23追加指示: IaCは定義・静的検証までとし、適用は他の作業を終えてから利用者が実施する。この作業ではplan/apply・実AWS試験を実行せず、適用不要のタスクを先行する。[適用後の具体的な実施手順](AWS_ACCEPTANCE_RUNBOOK.md)と[要件対応・未実施項目](FINAL_ACCEPTANCE.md)を引き継ぐ。以下の予算・正式名・復元後取得・後始末の制約は、将来の実施時にも維持する。

## 確定済みの制約

- Docker/SeaweedFS・fake/HTTPで必要な検証を先に完了する。大量件数・multipartの大容量相当・故障注入は実AWSで繰り返さない。
- us-east-1の構成と既存の外部認証経路を使用する。ソースIAMユーザのアクセスキーは利用者がコンソールで発行する既存方針を維持し、プログラムやドキュメントへ秘密値を保存しない。
- 実AWSのインデックスも通常DBと同じ形式。実データ用の試験prefixとインデックス用のprefixを分ける。
- SDKを含め自動リトライなし。実データの対象/状態は各実行の実ストア照会で判断する。

## 確定した範囲（D-10）

1. 専用試験prefixへ1 MiB以下のStandardファイルを最大2個用意し、3方向コピー、属性、一覧/JSON、再照合、削除を確認する。
2. 4 MiB以下の小さいインデックスで、ローカル→外部転送→S3→外部転送→ローカルの同形式利用を確認する。条件付き取得・保存と意図的な1回の版競合を確認する。通常のls/GUI閲覧のS3 APIは0回とする。
3. Deep Archiveは1 MiB以下の1個だけ用意し、Bulk・保持1日の復元要求を1回送る。復元後の取得・内容一致まで確認する。受付だけで完了扱いにしない。
4. 完了待ちは製品CLI/GUIへ実装しない。最終検証手順から明示的に状態確認する。待機上限72時間・再要求なしとし、上限で未完了なら未検証を記録して試験データを後始末する。AWSの通常所要時間は完了期限の保証ではない。
5. 試験データ・試験インデックス・未完了multipartを削除し、バケット全体が空であることを確認する。バケット・IAMロール/ユーザは削除せず運用へ引き継ぐ。

## 数量と見積り

実ストア試験のS3リクエストは全体で最大1,000回、作成する試験オブジェクトは最大10個、同時保存量20 MiB以下、外部への転送合計20 MiB以下、保持は最大72時間とする。Deep Archiveの最低保管期間分の料金は削除後も見積りに含める。上限へ近づいたら新しい試験を開始せず、残した試験データの削除を優先する。最終実施時に公開料金を再確認し、この範囲で実行計画を具体化する。

2026-11-22取得のus-east-1公式料金データでは、StandardのPUT/COPY/POST/LISTは0.000005 USD/要求、GET等は0.0000004 USD/要求、最初の50 TBのStandard保存は0.023 USD/GB月。Deep ArchiveのPUTは0.00005 USD/要求、Bulk復元要求は0.000025 USD/要求、Bulk取り出しは0.0025 USD/GB、保存は0.00099 USD/GB月。

上記数量の概算に余裕を持たせ、要求1,000回すべてを0.0001 USDで計算して0.10 USD、外部転送20 MiBには実単価ではなく予備単価1 USD/GBを当て約0.02 USD、保存・Deep Archive最低180日分・40 KB/個の追加メタデータ・取り出し分を加えても、計画用の予備枠0.20 USD以内を目安とする。確定上限1 USDには十分な余地を持たせる。既存の別用途のAWS利用や無料枠の残量を前提にしない。料金請求の遅延を利用した予算管理ではなく、試験自体の数量を制限する。

## バケット名・残すリソース（D-11/D-12確定）

- バケット名は `cress-archived-data`。以前のarhivedは誤記として訂正した。最終フェーズで利用可否を確認し、利用できなければ停止してユーザと再考する。代替名を自動採用しない。
- 既存リソースを無断で取り込んだり、試験対象外のデータを削除したりしない。後始末対象は本試験で作成した記録で追跡する。
- バケットは空にして残し、IAMロール/ユーザはそのまま流用する。Terraform構成とstateを運用管理へ引き継ぎ、試験専用の作り直し・全体destroyを前提にしない。試験のためだけの権限拡大や、試験終了時の運用データ自動削除ルールは追加しない。
- バケット内に予期しない試験外データがある場合は自動削除せず、空であるという完了条件を未達として通知する。新設した専用バケットでの試験を前提にし、既存データを消して試験環境を作らない。
