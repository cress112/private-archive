# 一覧専用GUI 設計メモ

2026-11-22、P2-02/P3-02の具体方式を[Phase 2・3実装設計](../PHASE2_3_DESIGN.md)に確定した。以下はPhase 1からの段階的検討記録を含み、残論点の現行解決は同実装設計を優先する。
全体設計: [../../../DESIGN.md](../DESIGN.md)。要件: [REQUIREMENTS.md](REQUIREMENTS.md)。要件と具体的な技術選定は確定済み。Phase 2完了後、P3-03〜P3-10の起動・階層/詳細/ソート・再読込・再照合・設定編集・取消・.app・大件数/ARM GUIを実装・検証した。進捗は [TASKS.md](../TASKS.md)、使い方は [GUI README](../../../crates/gui/README.md) を参照する。GUIはPhase 3で段階的に提供する。

## 確定した構成方針

- Slintの独立アプリとしてCLIと分離し、共通コアを再利用する。
- CLIと同じ設定・インデックスを利用する。
- Finderのカラム表示に倣い、バケット→ファイル階層を横並びの列で表示する。各行は名前と種別を中心にし、選択対象のサイズ・保存クラス・復元状態等を右の詳細欄へ基本10項目としてまとめる。フォルダ選択で右隣に子を表示し、0件は空の列にする。本文・サムネイルは取得しない（2026-11-21確定）。
- 列幅は初期245px、右境界8pxのTouchAreaを押してドラッグし160〜720pxに制限する。押下時の幅とウィンドウ上のポインタ座標を基準にし、境界自身の移動でドラッグ量がずれないようにする。行高は24px。外側ScrollViewは表示高に固定して横スクロールのみ、内側ListViewは列ごとの縦スクロールのみとする。列幅と縦位置はUIモデルが持ち、snapshot更新では列位置の幅・同一scopeの縦位置を引き継ぐ。永続設定やindexドメインへ表示寸法を追加しない（2026-11-23追加要求）。
- カラムから選択した対象への再照合を提供し、未登録ディレクトリのURIを直接入力する機能は要求しない。トップレベル更新はインデックスの記録済みバケットを列挙し、各バケット配下を再照合する。AWSからのバケット自動発見は行わない。
- 記録済みバケットがない場合、GUIのトップレベル更新にリモート照会対象はない。CLIで最初の対象を取り込み、GUIはローカル再読込でその記録を表示する。
- バケット一覧はオブジェクトから導出し、バケットだけの管理対象を保持しない。最後のオブジェクト記録がなくなったら該当バケットのノードも消える。内部索引の具体方式はadapter内で設計する。
- 設定値更新UIを今回の完成範囲に含め、CLIと同じ設定ファイル・検証契約を使う。設定操作だけでS3照会・インデックス移行を行わない。
- ignoreは表示起点URIに固定して表示し、展開・選択では基準を変えない。再照合では更新対象ディレクトリを基準とする。トップレベル表示・更新では各バケットルートを基準とし、バケット名を相対パスへ含めない。
- shell-scripts側のラッパーから認証プロファイル等の実行環境を受け取る。具体的なロール名・プロファイル名をGUIへ固定しない。
- ローカルの閲覧・再読込と、指定ディレクトリ配下の再照合を別の経路にする。起動・フォルダ選択・通常の再読込からS3アクセス経路を自動実行しない。
- macOSおよび将来のARM macOS・ARM Linuxへの移行を考慮し、UI固有の型・プラットフォーム依存をコアへ持ち込まない。

## 明示操作の基本方針（2026-11-21確定）

- 構成をなるべくシンプルにし、処理は利用者の明示操作で開始する。自動監視・定期更新・バックグラウンド再取得は追加しない。フォルダ選択によるローカル問い合わせ、明示ローカル再読込、S3への再照合を区別する。
- 再照合は選択配下を既定で深さ無制限に再帰更新し、必要時は深さ指定可能。ローカル再読込はURIで選択階層を保持し、消えた場合は残る親へ戻す。画面状態は起動中だけ保持する。

## 設定・中断・選択対象（2026-11-21確定）

- 設定UIは設定作成・保存・キャンセル・項目を既定値へ戻す操作を提供する。一時上書きは起動引数だけ。保存は進行中の要求へ影響させず次の操作から適用し、起動引数の上書きを維持する。ローカル再読込では共有設定も読み直し、インデックス保存先が変われば新しいルートへ表示を戻す。
- GUIの再照合は同時に1つとし、実行中の件数・対象に基づく進捗とキャンセルを提供する。閉じる操作は確認画面なしでキャンセルして、既定の最大50秒予算で後始末してから終了する。他のCLIプロセスを排他する仕組みにはしない。
- 単一選択を使い、ディレクトリ・バケットは配下、ファイルは完全一致の1件だけ照合する。ファイルでは再帰・深さを適用せず、複数選択の一括照合は追加しない。
- ローカル再読込と再照合を別の操作として提供する。共通用語は全体要件の確定した用語表に合わせ、再読込/Reload・再照合/Reconcile・取得/Fetchを区別する。CLIの最上位reconcile/restoreとGUI起動引数はD-01〜03で確認済み。共有設定・ユースケースとの具体的な接続を設計する。

## 起動とmacOSアプリ化

- 独立バイナリ・ラッパーの起動コマンドは `private-archive-gui`。--config / --index-location / --data-class / --restore-tier / --ignore / --log-levelを受ける（設計D-03確定）。引数なしは共有設定と既定値で起動する。
- 個人のMacで使う `Private Archive.app` を、標準的なバンドル構成でスクリプトから生成する方針とする。GUI本体・起動ラッパー・必要なリソースを同梱し、移動後もバンドル内部の相対配置で起動できるようにする。
- GUI本体はAWS SDKの標準認証経路だけを使う。外側の起動ラッパー相当が、既存CLIと同じプロファイル選択・認証環境整理を担う。具体的なロール/プロファイル名をGUI本体へ固定しない。秘密値をバンドルへ含めない。
- macOSの既存codesignによるローカル署名で、自分のMacから起動する構成を検証する。新たなアカウント登録・配布基盤を利用者の必須準備にしない。現在のx86_64 macOSで、通常起動・設定/インデックス読取・S3 API 0回を実際に確認する。生成・署名だけで起動検証済みとしない。
- 基盤調査: 現在のMacはmacOS 12.7.6で/usr/bin/codesignを利用できる。P3-03でSlint 1.19.0のビルド・可視ウィンドウ・software描画と共有設定/DB接続を確認済み。.appの生成/署名はP3-09、総合GUI受入とLinux ARM64描画はP3-10で検証する。

根拠: [Appleのバンドル構成](https://developer.apple.com/documentation/bundleresources/placing-content-in-a-bundle)、[SlintのmacOS Packaging](https://docs.slint.dev/latest/docs/slint/guide/platforms/desktop/packaging/macos/)。後者は自分のMacで動かすためのad-hoc署名を記載している。

## 描画基盤（2026-11-22、D-08確定）

WinitバックエンドとSlintのsoftware rendererによるCPU描画を採用する。GPU設定を利用者に要求せず、Qt/Skiaを必須依存にしない。必要なCargo featuresだけを有効にし、MacはOSのウィンドウ環境、Linux ARM64のDocker検証はX11/Xvfbを使う。LinuxのX11/フォント等の依存は検証イメージへ含める。

UIイベントループはメインスレッド、DB・ネットワーク・ソートはworker/Tokio側へ置き、Slintのイベント通知で結果を渡す。バックグラウンド処理は明示操作から開始し、自動同期・監視は追加しない。有界キューとページ取得でUIに全件を保持させない。

Slintの採用版・featuresは現在のmacOS 12.7.6でビルド/起動できる組合せを固定し、Docker ARM64とともに検証する。CPU描画方式の承認を対象OSでの実動作確認と混同しない。
根拠: [Winit backend](https://docs.slint.dev/latest/docs/slint/guide/backends-and-renderers/backend_winit/)、[Cargo features](https://docs.rs/slint/latest/slint/docs/cargo_features/index.html)。

## 検討案

- インデックスの抽象的な読み取り契約から階層を構築し、フォルダ選択に応じた列単位の取得等で全キーの一括保持を避ける。
- 再照合はCLIと同じユースケースを呼び、取得済みの部分反映と失敗通知を表示へ渡す。GUIからCLIプロセスを起動することを前提にしない。
- UIイベントループ上でDB・ネットワーク処理を長時間実行せず、Tokio等との接続方式を正式な設計で決める。
- 設定の読み取り・検証・保存をCLIのcfgとGUIの設定画面から再利用する。操作・保存後の適用は上記要件を使い、具体的な共有API・UI部品・安全なファイル保存の接続を設計で決める。
- CLI用・GUI用ラッパーのプロファイル選択・認証環境の扱いは共通方針にそろえる。コマンド名・ファイル配置・バイナリ名は設計段階で決める。

Winit＋CPU描画はD-08で確定。クレート構成・モデル・採用版/features・非同期接続等の現行設計は、冒頭のPhase 2・3実装設計を参照する。以下の段階的検討記録だけを未決事項と解釈しない。

## ソート操作（2026-11-22、D-09a〜c確定）

画面共通のソート条件リストを持ち、属性/昇降順の選択、条件の追加・削除・上下移動を提供する。既定URI昇順、左から優先し、CLIと共通のSortSpecを各列のローカルqueryへ渡す。変更時は表示URIによる選択を保ちながら列のページを取り直す。S3照会は行わず、設定ファイルへ書かない。条件は起動中だけ保持し、再起動で既定へ戻す。


## P3-04〜P3-08の接続（2026-11-23）

`browser`が列のquery sessionとURI/種別の選択、`cache`が全列共通32MiB以下のLRU、`settings`が保存済みraw値と有効値、`reconcile`が明示更新の組み立てを所有する。Slint custom Modelは必要な行を有界queueで要求し、UI threadでDBを待たない。再照合は別task/開始時設定とCancelContextを持ち、進捗通知は集約し、古い表示応答は世代で棄却する。

Slint基本要素の共通操作部品を `ui/controls.slint` に置いた。フォーカス用要素がマウスを覆わないようにし、実ポインタとキー入力も受入で確認した。設定・表示にS3 clientを作らず、明示再照合だけがCLIと同じcore/infraへ接続する。[検証記録](../../PHASE3_VALIDATION.md)を参照。

## P3-09の配布接続（2026-11-23）

- シェルwrapperは `scripts/private-archive-gui.sh`。既存CLI wrapperと同じ認証環境整理・profile優先順位で、argvをshell文字列評価せず転送する。
- `scripts/macos/launcher.c` は `_NSGetExecutablePath` とrealpathから同じMacOSディレクトリのGUIをexecする。相対配置でbundle移動に追随し、環境整理/profile選択はlauncherへ限定する。
- `scripts/package_macos.py` は既存native GUIを一時bundleへcopyし、SDK clangでlauncherを生成、Info.plist/PkgInfoを作成してGUI→bundleの順にad-hoc署名する。新規出力先へ公開し、既存bundleを無断で置換しない。
- 通常版をLaunchServicesから起動した実画像、fixture版の同じbundle経由のモデルを確認し、生成/署名と実起動を区別した。[検証記録](../../PHASE3_VALIDATION.md)を参照。
