# 一覧専用GUI 要件

全体要件: [../../../REQUIREMENTS.md](../REQUIREMENTS.md)。2026-11-21に利用者向け要件・共通用語をレビュー済み。具体的な構成・引数はD-01〜12と[詳細設計](../PHASE2_3_DESIGN.md)で確定済み。Phase 2完了後、P3-03〜P3-10の起動・階層/詳細/ソート・再読込・再照合・設定編集・取消・.app・大件数/ARM GUIを実装・検証した。現行の実装範囲は [GUI README](../../../crates/gui/README.md) を参照。

## 合意事項

- Slintの独立アプリを今回の完成目標に含める。
- 構成をなるべくシンプルにし、利用者の明示操作を起点に処理する。フォルダ選択によるローカル表示、ローカル再読込、リモート情報の再照合を区別し、自動監視・定期更新は追加しない（2026-11-21、質問29の判断理由）。
- CLIと同じ設定・インデックスを利用し、共通のコアを再利用する。DB技術・S3 SDK固有の型へGUIを依存させない。
- GUIはFinderのカラム表示に倣い、階層ごとの一覧を横並びの列で表示する（2026-11-21、従来のツリーウィジェット案を置換）。最左列に既知バケットを並べ、フォルダを選択すると右隣にその内容を表示する。記録済みキーのprefixからディレクトリ相当の階層を構成し、オブジェクトを表示する。
- カラム境界を押しながらドラッグして列幅を調整でき、行高はコンパクトにする。階層が深い場合（10階層）に一覧部全体を左右へ、項目が多い場合（各階層300ファイル）にカーソル下の列だけを上下へスクロールできることを実GUIで確認する（2026-11-23追加要求）。
- 各列の行は名前とファイル/フォルダの区別を中心にする。選択した項目のサイズ・保存クラス・復元状態等は、右側の詳細欄へCLIと共通の基本10項目としてまとめる（2026-11-21、従来の各行4項目表示を置換）。本文やサムネイルを取得しない。未取得は不明とし、表示補完の追加リモート照会をしない。復元状態は最後に取得・記録した状態で、時計だけで書き換えず期限・最終照会日時を詳細に示す。
- ローカルインデックスの閲覧・再読込を提供する。初回の起動・フォルダ選択・表示・ローカル再読込でもS3を自動照会しない。ローカル未作成なら空で初期化できる。起動・閲覧・ローカル再読込で対象0件なら、エラー画面にせず空の列を自然に表示する（2026-11-21確定）。
- ローカル再読込は明示操作だけとし、URIで選択・開いている階層を保つ。対象が消えたら残る親階層まで戻す。画面状態は起動中だけ保持し、再起動用の履歴を保存しない（2026-11-21確定）。
- 操作者が指定したディレクトリ配下の再照合を提供する。更新対象の実ストア照会とインデックス更新にはCLIと同じコアを使い、指定範囲外を自動走査しない。
- 操作対象はカラム表示から選択し、「再照合」等の明示操作で更新する。カラム上の選択・既知バケットは要求する範囲の指定に使い、その範囲内の実データ状態は当該実行の実ストア照会で判断する。保存済みキー集合を実ストアの最新状態として信用せず、前回の未送信分や専用復旧状態を操作の前提にしない。未登録ディレクトリのURIを直接入力する機能は要求しない。
- 再照合はCLIの `reconcile` に相当する。選択したディレクトリ/バケット配下を既定で深さ無制限に再帰更新し、必要時は更新前に深さを指定できる。既定は `--recursive` だけを指定した場合と同じとし、深さ0は受け付けない（2026-11-21確定）。
- カラム上は1項目ずつ選択する。ファイルを選択した場合もその1件だけインデックス更新でき、再帰・深さ指定は適用しない。複数選択による一括更新は今回提供しない（2026-11-21、質問32確定）。
- トップレベルを選択した更新は、インデックスに記録済みのバケットだけを対象とする。各対象バケットを起点として配下を照会し、見つかった未記録キーも取り込む。AWSからバケット一覧を取得して対象を増やす処理は行わない。
- バケット一覧はオブジェクト記録から導出する。バケットだけを独立管理せず、最後のオブジェクト記録がなくなったバケットは最左列とトップレベル更新対象から消える。
- 初回などバケットの記録がない場合は、GUIのトップレベル更新の対象もない。新しい対象の最初の取り込みはCLIから行い、GUIはその記録を利用する。空のインデックスを理由にバケットの自動発見を行わない。
- 再照合では取得・インデックス更新そのものを要求操作とする。完了できなければ失敗を通知する。取得途中の失敗では取得済み反映を残し、未取得範囲の既存記録を削除しない。自動リトライ・ロールバック・破損時の自動再構築は行わない。
- ignore等の共通規則を適用する。ignore対象は新規にインデックスへ取り込まず、既存レコードは保持したまま表示・操作から除外する。
- 表示のignore基準は開いた表示起点URIに固定し、フォルダの選択・列の追加で変えない。再照合時は更新対象として指定したディレクトリを基準にする。トップレベル表示・更新では各バケットのルートを基準とし、照合する相対パスにバケット名を含めない。
- shell-scriptsリポジトリにGUI用のラッパーコマンドを含め、認証プロファイル等の実行環境を渡す。GUI本体に具体的なIAMロール名・AWSプロファイル名を固定しない。配置の共通方針は全体要件に従う。
- 現在のx86_64 macOSと、将来のARM macOS・ARM Linuxへの移行に対応する。設定・インデックスを移し、GUIを対象向けに再ビルドして継続利用できることを完成条件に含める。
- 今回のGUIは一覧閲覧・再照合・設定値更新UIを扱う。GUIからの実データのコピー・削除・復元等は将来の拡張候補とし、選択対象からローカルへコピーする操作等は必要時に別途要件化する。
- GUIは最後のPhase 3で提供する。作業単位と依存関係は [TASKS.md](../TASKS.md) に記載する。2026-11-20の検証範囲の追加合意により、現在のx86_64 macOSは実動作、Linux ARM64はDockerエミュレーションでARM版GUIの起動・描画・基本操作、ARM macOSは公式資料・採用依存関係の互換性調査を受入条件とする。ARM Macのビルド・実機実行は必須にしない。

## 明示操作と画面状態（2026-11-21確定）

- ユーザの判断原則は「なるべくシンプルに組む」「何か動かしたいときは明示的に実行するのを基本とする」。自動監視・定期更新・バックグラウンド同期・再起動用の画面履歴を追加しない。
- 表示済みの列をまとめて読み直す操作は「ローカル再読込」とする。DB変更の監視による自動表示更新は行わない。フォルダ選択に必要なローカルqueryは、その明示的な選択時点の情報を表示するために行う。起動時の全DBスナップショットを固定し続ける保証は追加しない。
- 再読込後はURIで選択対象・開いている階層を保ち、対象が消えたら残っている親階層まで戻す。状態は起動中だけ保持し、アプリ再起動後の選択・列の復元を要求しない。
- 表示が空でもS3を自動照会しない。新しい対象の初回取込はCLIから行う既存契約を維持する。再照合で正常に確認した空範囲は反映して成功とし、全件ignoreで確認不能なら失敗を通知する。既知バケット0件でトップレベルの照合範囲自体がない場合も失敗とし、S3照会しない（2026-11-21、D-04/D-06確定）。

## 進捗・キャンセル・終了（2026-11-21確定）

- GUIから開始する再照合は同時に1つだけとする。GUI内の進捗・中断の管理であり、他のCLIプロセスや実データ操作を排他しない。
- 当該実行で取得した対象・件数を使って進捗を表示する。事前に保存済みのインデックス件数を実ストアの確定総件数として信用しない。取得途中の総件数不明を表現できること。
- キャンセル操作で新規照会を止め、取得済み反映を残す。最初の停止から付属処理を含む最大50秒の共通収束予算で終了し、予算を取り直さない。自動再試行・ロールバック・次回実行への操作引継ぎはしない。
- 再照合中にウィンドウを閉じた場合は、確認ダイアログなしでキャンセルし、後始末後に終了する。DB・ネットワーク処理や停止待ちでUIを長時間ブロックしない（質問31確定）。

## 設定値更新UI

- 設定可能な項目をGUIから編集・保存できるUIを、今回の完成GUIに含める。CLIと同じ設定ファイルを使用する。2026-11-20に追加した `logging.level`（既定info、error/warn/info/debug/trace）も編集対象とし、設定と実行時指定の優先順位をCLIと共通にする。
- 値の検証、組み込み既定値と設定ファイルの関係、設定対象外の実行時必須入力等の契約はCLIのcfgと共通にする。復元保持期間を既定値として保存する機能は追加しない。
- 設定画面の表示だけで設定ファイルを暗黙に作成しない。設定ファイル作成・保存は利用者の明示的な設定操作として扱う。
- 設定操作自体ではS3へアクセスせず、インデックス保存先の変更は使用先の切り替えだけとし、旧DBの移動・統合・削除・リモート取得を自動実行しない。
- 「設定作成」「保存」「キャンセル」「項目を既定値へ戻す」を提供する。未作成時は明示的な設定作成で初期化し、既存設定を上書きする初期化はしない。保存時に値を検証し、キャンセルは未保存の編集を破棄する。「既定値へ戻す」は保存対象の明示値を取り除く意味とし、組み込み既定値を固定値として新たに保存しない（質問30確定）。
- 保存は進行中操作の設定スナップショットを変更せず、次の操作から反映する。起動引数による上書きは維持し、有効値と出所を確認できること。共有設定の外部変更も、明示的なローカル再読込で読み直す。
- インデックス保存先が変わったら、新しいインデックスのルートへ表示を戻す。旧DBの移行・統合は行わない。設定ファイルを読むだけでS3へアクセスしない。
- 保存しない一時的な上書きは起動引数だけで行い、専用の一時設定UIは今回追加しない。GUIは独立コマンドprivate-archive-guiを使い、--config / --index-location / --data-class / --restore-tier / --ignore / --log-levelを提供する（2026-11-21、設計D-03確定）。

## ソート（2026-11-22、D-09a〜c確定）

CLIのls --sortと同じ6値のenumを使い、条件を左から優先する。既定URI昇順、不明値は方向によらず最後、同値ならURI昇順。各列の直下項目へ同じ条件を適用する。条件/昇降順の追加・削除・優先順位変更を提供し、起動中だけ保持する。設定ファイルや履歴へ保存しない。ソート操作でS3を照会せず、全件をメモリ収集する構成にしない。詳細は全体要件の「一覧のソート」を正本とする。

## 設計段階へ引き継ぐ事項

- 全体要件で確定した「再読込 / Reload」「再照合 / Reconcile」「取得 / Fetch」を画面・CLI・コアの契約へ対応付ける。再読込と再照合は独立した操作として提供し、単独の「更新」で混同させない。
- 起動引数・サブコマンドの形式、Slintの列/詳細モデル、キャンセル・非同期処理・設定保存の具体的な接続。
- 各受入例を具体的な試験手順とGUIのメモリ・応答性の検証条件へ落とし込む。

GUIバックエンド・レンダラはWinit＋CPU描画をD-08で確定。ウィンドウ環境・配布方法・非同期処理の接続・具体的な実行時依存は、要件を満たす方式として設計段階で具体化する。

表示形式の参照: [AppleのFinder表示形式](https://support.apple.com/en-au/guide/mac-help/mchldaafb302/mac)。カラム表示の配置・階層移動の感触を踏襲し、ファイル本文のプレビューは今回提供しない。
