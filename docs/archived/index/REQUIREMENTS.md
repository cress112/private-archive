# index 要件

全体要件: [../../../REQUIREMENTS.md](../REQUIREMENTS.md)。2026-11-21に利用者向け契約をレビュー済み。残る具体方式は設計で定める。

## 合意事項・memoの前提

- インデックスはコスト低減のための状態の写しとし、実データの正本とは扱わない。保存場所にかかわらず最新状態の常時保証は要求しない。
- オブジェクト情報をローカルに保存し、通常の一覧をリモート走査なしで行えるようにする。
- 実データ取得以外の通常参照はインデックスのqueryだけで完結させる。管理対象の実オブジェクトを自動HEAD・LISTしない。
- インデックスファイルの保存先は設定可能とし、ローカルを既定に、S3オブジェクトも指定できるようにする。
- S3保存時はローカルコピーを保持し、更新系操作または再照合（CLIの `reconcile`、GUIのディレクトリ配下の更新）の要求時に限り、インデックス自体の変更確認・取得を行える。通常の `ls` やGUIの閲覧・ローカル再読込は初回でもS3 APIを発行しない。
- ローカルコピーが未作成なら空のインデックスを自動作成できる。通常の `ls` は空の結果を返し、CLIは対象0件として終了コード1にする（2026-11-20追加方針）。リモートインデックスの有無をS3へ確認しない。空のローカルコピーを根拠にリモートも未作成だと判断しない。
- 破損を検出したら、判明している箇所・原因を詳細エラーとして返す。呼び出し元は、更新系操作なら付属のインデックス異常としてwarningにし、lsの要求操作が完了できなければエラー終了とする。破損を未作成と見なさず、自動再構築・実ストアの走査・空への置き換えを行わない。
- CLIに依存せず、今回含める一覧専用GUIからも再利用できること。記録済みのキーから階層を構成し、ストアルート・ディレクトリ相当・オブジェクトを階層として扱い、GUIのカラム表示を支えられること。
- GUIのトップレベル→バケット→ファイル階層を構成でき、各列の行の名前・種別と、選択時の詳細10項目の取得を支えられること（2026-11-21のカラム表示への変更を反映）。トップレベルの再照合にはインデックスに記録済みのバケット一覧を返し、AWSからのバケット発見を行わない。
- インデックスの実現形式を差し替え可能にし、保存・検索・更新の抽象契約から具象DBを切り離す。
- SQLite・redb等の型・クエリ・テーブル・シリアライズ・DB固有のエラー型はinfra層のadapterへカプセル化する。コアの公開契約は具象DBに依存しない。
- adapterの変更のためにCLI・sync・インデックスの業務判断を変更する構成にしない。DB同士のファイル自動変換を保証するかは別の要件として扱う。
- S3固定の型にせず、将来のB2等の情報も扱えること。
- インデックスに存在するストアルートを列挙できること。
- 管理単位はオブジェクトとし、バケットだけを独立管理しない。ルート一覧はオブジェクト記録から導出し、最後のオブジェクト記録がなくなったバケットはルート一覧から消える。ignoreで非表示にしただけの既存レコードは保持するという契約を維持する。
- 非再帰の一覧は指定対象の完全一致を扱い、オブジェクトとディレクトリ相当を区別して返せること。
- 深さ指定は起点の直下を1、その次を2として検索でき、未指定なら再帰深さを制限しない。
- CLIの深さ指定は全コマンドで再帰指定との併用を必須とし、単独指定と深さ0は入力エラーとする（2026-11-19確定）。
- cp・rmの対象選択では完全一致キーと配下prefixを区別できること。再帰rmの `foo`・`foo/` は `foo/` 配下だけを対象とし、キー `foo` 自体や `foobar/` 配下を含めない。
- 復元要求でも同じ完全一致・配下prefix・深さの規則で対象を扱えること。復元中・復元済み・即時取得可能な状態を、取得済み情報から実行可否判断に利用できること。
- 詳細表示・JSONのためにURI・種別・サイズ・保存クラス・復元状態・復元期限・元の更新日時・元の作成日時・UNIX権限・最終照会日時を返せること。未取得の値は不明として区別し、検索時に値を埋めるためのリモート照会を行わない。
- CLI一覧の既定はURIの昇順とし、大文字小文字を区別し、言語・地域設定に依存しない。ディレクトリ相当・ストアルートのサイズ等は配下を合算せず不明として返す（2026-11-20確定）。全件のメモリ収集をソートの前提にしない。
- 最終照会日時は実ストアの対象情報を照会した日時を表す。インデックスquery・表示・S3上のインデックスの取得だけで更新しない。元の更新日時とS3のLast-Modifiedも区別する。
- 復元状態は不要・未復元・復元中・復元済み・不明とし、通常一覧は最後に取得・記録した状態を返す。保存済み期限が過ぎても時計だけで記録を書き換えない。JSON値はnot_required/archived/restoring/restored/不明null（2026-11-20確定）。
- S3書戻しは変更があれば終了時1回。ローカルは随時反映し、途中失敗・Ctrl+C時も収束予算内で書戻しを試みる。競合した他の更新を上書きせず、その実行内で通知して終える。ローカル反映は参照用の写しとして残せるが、未送信分の永続管理・再送キュー・専用復旧を設けない。自動マージ・再試行は行わない（2026-11-20、質問19の追加指示を反映）。
- 再照合で外部の追加・変更・削除を反映できること。
- 更新操作では、指定範囲の事前照会結果と、その後に成功した操作結果を反映できること。古いインデックスだけで更新対象を決めない。
- 明示的な再照合は指定範囲のみ行う。プログラムが「全範囲」を自動で把握・更新することは要求しない。
- インデックスの取得・初期化・読み取り・書き込み・保存等の失敗は詳細に返せること。更新系操作の呼び出し元はこれをwarningとして扱い、実データ操作の実行判断・成否に影響させない。`reconcile` は更新そのものが要求操作であり、完了できなければエラーとする。
- 再照合の列挙途中で失敗した場合は、取得済みの反映を残し、未取得範囲の既存記録を削除しない。処理全体の原子性は要求しない。
- CLIとSlintの独立GUIで同じ設定・インデックスを使い、GUIのローカル再読込と指定範囲の再照合にも同じ契約を適用する。
- 配置元のローカルファイルパスは保存不要。
- 検索・更新のために全レコードをメモリに保持しないこと。
- 通常の検索は有効なignoreに従い、既存レコードであっても除外対象を一覧に表示しないこと。
- ignore対象を新規に取り込まない。既存レコードは保持し、ignore適用中は表示・操作対象から除外する。設定の解除だけで未記録対象を自動取得せず、必要な範囲の再照合で取り込む。除外対象を記録から削除する根拠にしない。
- ファイルの更新日時・作成日時・UNIX権限は取得できる範囲で扱い、属性不足はデータ操作成功を妨げない。保存できた元の属性を再構築後も可能な限り維持する。保存先は設計段階で決める。
- ignoreは記録済みの情報にも適用し、対象を直接指定してもwarningで除外する。照合には実行時指定まで解決済みの有効パターンを使う。
- リモートのignoreは指定された操作対象を基準に照合する。同一オブジェクトの除外結果がすべての操作基準で固定になることは要求しない。
- 保存形式は、対応OS・アーキテクチャを移してCLIを再ビルドした後も利用できること。追加の実行時DBライブラリの導入を必須にしない。
- OS標準ランタイムへのリンクは許容する。pure Rustに限定せず、追加の実行時依存が不要な実装を選べること。
- 複数CLIプロセスの参照・更新を想定し、完了した操作の結果を完了順に反映する方針とする。操作状態の永続管理・コマンド全体の原子性は要求しない。

## 保存先から独立したファイル契約（2026-11-22、D-07確定）

- 同じDB adapterのファイルはローカル/S3で同一形式。整合済みのDBを外部ツールでコピーし、index.locationだけを変更して利用できること。S3専用形式・必須の付随メタデータを要求しない。
- indexクレートに保存先判定、ETag、条件付き取得/保存、転送キャッシュを持ち込まない。保存先adapterがバイナリの転送を担当する。
- IndexRead/IndexWrite/IndexSnapshot等はDB非依存のportとし、ファイルのシリアライズ/デシリアライズ・形式検査はinfraのDB adapterへ閉じ込める。SQLite/redb等はadapterとして差し替えられる構成にする。DB形式間の自動変換は別問題であり提供しない。
- ETagを持たない手動コピー済みファイルも使用可能とする。取得省略に使う情報はDB本体に埋め込まず、参照先が移動してもDBの論理内容を変更しない。

## 設計・検証へ引き継ぐ事項

- 移植性の検証範囲は全体要件で確定。現在MacとDockerのLinux ARM64で同形式の設定・インデックス共用を確認し、ARM macOSは互換性調査とする。具体的な試験手順は設計・検証タスクで定める。
- インデックス異常の具体的な表示形式。
- 破損時の退避・別の正常/新規保存先選択・指定URIの再照合は明示手順として提供する。専用の未送信復旧・操作再生機能は追加しない。具体的な手順をP2-13で完成させる。
- 復元状態の値一覧・期限超過記録の表示、ls結果JSONの10キー・不明null・UTC RFC3339・バイト整数・権限8進数文字列は全体要件で確定。URI/ストアの既存識別設計と基本メタデータ・最終照会日時の意味を維持する。
- CLI/GUI共通の6値のenum（name/size/uriのasc/desc）によるSortSpecをquery portへ渡す。左から優先、既定uri-asc、不明値は方向によらず最後、同値はURI昇順。全体要件のD-09a〜cに従い、全件をメモリ保持せず、指定順序でのページ取得をDB非依存のportで提供する。
- ローカル削除検知の完了条件と同時更新の保護はDESIGNに記載する。S3同期は終了時1回・競合をその実行内で通知・自動マージなしと確定。保存先は切り替えだけ、形式/未対応スキーマの自動変換なし。未送信分の永続管理・専用復旧なし。S3同期の具体方式は設計レビューで決める。
