# sync 要件

全体要件: [../../../REQUIREMENTS.md](../REQUIREMENTS.md)。Phase 1 cpは2026-11-15の合意を反映し、残るPhase 2/3の契約と区別する。

## 合意事項・memoの前提

- CLIから独立したデータ操作のコアを提供する。
- インデックスの具象DBにも依存せず、抽象契約を通して保存・検索・更新を要求する。SQLite・redb固有の型・クエリ・テーブル操作をsyncの業務処理へ持ち込まない。
- 初期はS3を扱い、port / adapterで将来のストア追加に備える。
- 読み取り（load）と書き込み（save）の責務を分離する。
- 対応する任意URIを操作できること。
- ローカルとリモートのコピー、再帰操作、復元要求・状態確認、削除、明示的な再照合を提供する。
- Phase 1 でローカル→S3・S3→ローカル・S3→S3の組み合わせを提供する。
- コピーは新規作成または上書きとする。
- コピー先の解決はAWS CLIのパス規則に合わせ、再帰ではコピー元からの相対構造をそのままコピー先へ配置する。
- `rm` の対象選択もAWS CLIに合わせる。非再帰では完全一致キーだけ、再帰では指定末尾を `/` にそろえた配下prefixだけを対象とする。再帰指定 `foo`・`foo/` は同じ範囲であり、完全一致キー `foo` や `foobar/` 配下を含めない。
- cp・rmのAWS互換はパス解釈・対象選択・コピー配置に適用し、ignore・即時停止・自動リトライなし・属性のbest effort等の共通要件を維持する。
- 再帰の深さは起点の直下を1、その次を2と数え、指定なしで制限しない。
- CLIの `cp`・`ls`・`rm`・`restore` は深さ指定に再帰指定の併用を必須とし、深さ0を受け付けない。復元はURIごとに検証する（2026-11-19確定）。
- 外部ツールによる追加・変更・削除を想定する。
- 更新操作は、指定範囲の実ストア照会 → インデックス反映の試行 → 実ストア照会結果による実行可否の判定 → 実操作 → 成功結果のインデックス反映の試行、の順に行う。付属のインデックス反映が失敗しても照会結果を使って要求操作を実行できること。
- 通常の一覧は記録済み情報のみを使う。再照合では指定範囲の実データを照会してインデックスへ反映し、結果件数を返す。CLIの一覧表示は別のls、GUIは当該操作結果を表示へ反映する。
- 再照合は有効範囲を正常に照会して空と確認・反映できれば成功。全件ignoreで有効対象を確認できない場合はエラーとし、削除照合へ進まない。権限・通信失敗で未取得の対象を削除しない。除外通知とその集計を呼び出し元へ返し、未走査配下の件数を推測しない（2026-11-21、D-04/D-06確定）。
- 再照合はCLIの `reconcile` とGUIの指定ディレクトリ配下の更新から再利用できること。GUIでも取得・更新不能は操作失敗とし、途中の取得済み反映と未取得範囲の既存記録を残す。GUIの閲覧・起動・ツリー展開・ローカル再読込ではリモート照会しない。
- 通常の一覧は、初回でもS3 APIを発行しない。リモートインデックス自体の変更確認・取得も行わず、未作成ならローカルの空のインデックスだけを初期化する。
- インデックス破損を検出したら判明した詳細を通知し、自動再構築や修復目的のS3走査を行わない。更新系操作ではwarningとして要求操作を継続し、lsの要求操作自体を完了できない場合はエラーを返す。
- 更新時は以前のインデックスに記録されていない対象も、その実行で取得した実ストアの照会結果に従って扱う。ローカル・S3インデックスや前回の同期成否を実行可否判断の根拠にしない。実行内の一時manifestを次の実行の復旧情報として再利用せず、未送信キュー・実行をまたぐ準備/回復状態は追加しない。指定範囲外を自動で全走査しない。
- 最初の要求操作の失敗で残りを停止し、自動リトライしない。コマンド全体のatomicityと成功済み操作のロールバックは要求しない。
- cp・rm・復元で範囲・深さ・ignore適用後の対象が0件なら、要求処理を実行できないエラーとする。不存在・再帰配下0件・全件ignoreを含む（2026-11-20追加確定）。フロントエンドのログレベル指定・ログ抑制によって対象選択や要求操作の成否を変えない。
- 削除・復元は1件ずつ要求し、前の要求の成否を確認してから次へ進む。削除はキー昇順、復元はURI指定順・各URI内キー昇順とする。オブジェクト間の並列実行オプションは任意の改善候補であり、今回の必須実装には含めない（2026-11-19確定）。
- 削除・復元の中断・要求失敗時は新規要求を止め、最初の中断・失敗から付属処理込み最大50秒の予算内で発行済み要求の終了確認と、確認済み成功の通知・インデックス反映を試みる。応答を確認できない要求は成否不明として返す。自動再試行・確認のための追加照会・成功済み操作の取り消しは行わず、予算を段階ごとに延長しない（2026-11-19確定）。
- アップロード失敗・キャンセル時は、その操作が開始した未完了multipart uploadの中断・パート削除を試みる。他プロセスのアップロードは一括中断しない。後始末失敗は元の失敗・中断に加えてwarningを返し、要求操作の成否を変えない。
- コアは失敗の内容を詳細に返し、CLI固有の表示とは分離する。
- 更新系操作では、インデックス関係の取得・初期化・読み取り・書き込み・保存等の失敗はwarningとして呼び出し元へ通知する。利用可能なインデックスの有無に依存せず要求操作を実行でき、その成否だけで正常終了・エラー終了を決める。必要な実ストア照会やキー解決の失敗とは区別する。
- `reconcile` は取得・インデックス更新自体が要求操作であり、これを完了できなければエラーを返す。列挙途中の失敗時は取得済みの更新を残し、未取得範囲の既存記録を削除しない。
- 約100 GBの単一ファイルを扱え、本文サイズ・対象件数に比例してメモリを消費しないこと。
- Tokioによる非同期処理を用い、列挙・本文・結果を逐次処理すること。
- 保存クラスは組み込み既定値standard、設定値、実行時指定の順に上書きできること。
- 復元保持期間は呼び出し元から明示的に受け取り、コアで既定値を補完しない。
- 復元方式の組み込み既定値はBulkとし、設定・実行時指定で変更できる。
- 復元要求は受付後に結果を返し、今回の完成範囲に完了までの待機・自動ポーリングを含めない。
- 1回のユースケースで複数URIを復元対象にでき、復元期間・方式は全体共通、再帰・深さはURIごとに受け取る。ある対象の再帰指定を別の対象に引き継がない。
- 復元要求開始前に全URIを再帰・深さ・ignoreに従って具体的なキーへ解決し、同じストア・バケット・キーの重複を排除する。同一対象への要求は1回だけとし、解決途中で失敗した場合は復元要求を開始しない。キーの全件メモリ保持は行わず、実現方式は設計段階で決める。
- 復元はURIの指定順、各URI内はキーの昇順で実行し、重複は最初の出現に割り当てる。全URIの解決・重複排除後に全対象の取得済み実ストア情報で事前可否検査を行い、不適格な対象が1件でも判明したら復元要求を一切送らない。付属の事前インデックス反映は残ってよい。事前検査後の状態変化やAPI失敗では即時停止し、受付済み要求を取り消さない（2026-11-19確定）。
- 復元可否が不明な対象に限って追加照会する。それでも可否が確定しない対象・照会失敗が1件でもあれば全体を失敗とし、復元要求は0件のままにする。この照会は要求操作に必要な情報経路で、付属インデックスのwarning扱いとは区別する。通常一覧には接続しない（2026-11-20確定）。
- 復元の再帰範囲はcp・rmと同じ配下prefixの規則とする。`foo`・`foo/` は `foo/` 配下だけを対象とし、キー `foo` 自体や `foobar/` 配下を含めない。
- 復元中・復元済み・Standard等の即時取得可能な対象への復元要求は詳細エラーを返す。事前照会で判断できれば復元API送信前にエラーとし、warningでスキップしたり期限更新したりしない。最初の失敗で停止し、受付済み要求を取り消さない。
- S3の復元期間は日単位で扱い、CLIは日・週の表記を提供する。時間表記を丸めて受け付ける要件はない。
- 復元コピーの解放・保持期限短縮の専用ユースケースは要求しない。再アーカイブ専用操作 は対象外。
- 共通のignoreを全操作の対象選択に適用する。除外対象にはコピー・復元・削除等の操作を実行しない。
- 再帰の既定対象は、隠しファイル・隠しディレクトリ配下を含む指定範囲・深さの全ファイルとする。`.DS_Store`・`.git/` 等を暗黙に除外せず、設定または実行時ignoreで明示された場合だけ除外する。symlink・特殊ファイルと走査失敗の扱いは既存契約に従う（2026-11-19確定）。
- ignore対象は事前照会・再照合で新規にインデックスへ取り込まない。既存レコードは削除せず保持し、表示・実操作から除外する。ignore解除後の未記録対象は再照合で取り込む。再照合時もignoreによる未取得をリモート削除と見なさない。
- ignoreされていないシンボリックリンクはエラーにし、空ディレクトリは保存・復元しない。
- 指定ファイルを1ファイル1オブジェクトとしてそのまま転送し、自動圧縮・展開・集約は行わない。
- コピー操作は内容の転送成功を正常終了の条件とし、更新日時・作成日時・UNIX権限の保存・復元はbest effortとする。属性不足・非対応・保持失敗はwarningとし、内容の転送成功をエラーにしない。
- 所有ユーザ情報は保持しない。保存できた元の属性はインデックス再構築後も可能な限り維持する。
- ignoreに一致した対象は直接指定されてもスキップし、直接指定の除外はwarn、再帰の個々の除外はdebug相当の通知として扱う。コアからURI・パスを含む除外の通知と集計を返せ、CLI固有の表示・ログライブラリに依存しないこと。全件ignoreなら対象0件エラーとする（2026-11-20）。
- 設定値の解決では実行時指定を最優先し、解決済みの値を使う。明示指定必須の項目にコアの既定値を補完しない。
- ignoreの記法だけをgitignoreと同様にし、Git設定・`.gitignore` は参照しない。
- ignoreの照合基準はローカルではCWD、リモートでは指定された操作対象とする。基準変更で除外結果が変わることを許容する。
- 複数CLIプロセスによる同時操作を想定し、操作状態の明示管理・コマンド全体の排他・実データ競合の追加検知を要求しない。SDKの操作エラーは詳細に返す。
- 操作が完了した順に結果をインデックスへ反映する方針とする。
- 追加の実行時ライブラリ・外部コマンドを必須にしない。pure Rust自体は必須条件にしない。
- OS標準の共有ライブラリ・ランタイムへのリンクは許容する。
- 具体的なIAMロール・AWSプロファイル名をコアに固定せず、外部設定をSDKの標準認証経路で利用できること。

## Phase 1 cpの追加合意

- cpは全対象のURIと配置先を本文転送前に解決・照会し、一時manifestへ記録する。新規宛先は作成する。解決中の失敗では本文転送を始めず、全体snapshot・独自競合ガードは追加しない。
- 外部削除の具体的な照合方式は [index設計](../index/DESIGN.md) に記す。cpの事前照会では宛先prefix全体の削除照合をしない。
- cpは新規処理を止め、発行済み要求の確認と後始末を上限内で試みる。確認済み成功は表示・反映を試み、応答不明はUnknownと通知する。rm/復元の逐次実行と中断収束予算は上記の2026-11-19確定契約に従う。
- cpの途中再開は含めない。local宛先は一時ファイルから成功時だけ置換する。サイズと可能なchecksumを検証し、不一致はerror、checksumなしの外部objectはwarningで続行する。
- FIFO・socket・device等はignore対象外ならerror。
- 単一リモートobjectのignoreは親prefix、localはCWD基準。cpは元と解決後宛先の両方に適用し、どちらかの除外でskipとする。通知レベルは直接指定warn・再帰の個々の対象debugという上記契約に従う。
- 複数URIの復元順序・全件事前検査は上記の2026-11-19確定契約に従う。
- Phase 1のメモリと転送の受入は [転送・検証計画](../TRANSFER_VALIDATION.md) に記す。移行の実機確認はP2-11。

Phase 1のmultipart・一時ファイル・port・workerは [全体設計](../DESIGN.md) と転送計画で定める。依存ライブラリの実測は実装タスクで行う。

## 調査済みの実装上の制約

- S3→S3はサーバー側コピーが可能。100GBのコピーにはmultipartが必要であり、固定5MiBでは10,000パートの上限を超える。
- S3 SDKは既定でリトライするため、合意済みの自動リトライなしを明示的に反映する必要がある。
- 未完了パートには保管料が続き、Deep Archive向けでも途中のパートはStandard相当となる。未完了分の削除に早期削除料金はない。失敗・キャンセル時の中断を試み、Terraformには開始1日後から中断対象とするLifecycleを含めると合意した。Lifecycleは実行中の転送にも適用されうる。
- LISTで取得できる状態と、GET・HEADで取得できる元ファイルの属性を区別する。通常参照が全件HEADする構成にしない。
- 根拠と詳細は [全体要件の追加調査](../REQUIREMENTS.md) に記載する。

## 保存先とDB形式の独立（2026-11-22、D-07確定）

インデックスのDB portと、ファイルをバイナリとして取得・保存するportを分離する。DB形式はDB adapter、S3のETag・条件付き転送は保存先adapterへ閉じ込め、indexクレートに保存先の知識を持ち込まない。CLI/GUIで同じ調整処理を使い、保存先を移しただけでDBファイル形式を変更しない。
